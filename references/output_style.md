# 中文輸出文風指南

翻譯、重寫、修稿或 review 中文段落時，依本檔核對資訊是否忠實、措辭是否自然，以及語氣與文章氣質是否符合任務。 判斷輸出是否像自然的臺灣繁體中文技術文章時，也要連同句子之間的承接與整段讀感一起閱讀

檢查具體標點、空格、Markdown syntax、citation apparatus、link label 與正式輸出檔污染邊界時，查閱 `references/output_grammar.md`。 可直接對應 linter surface signal 的局部句法規則也由該檔定義，與本檔對忠實度、語氣及整段行文的判斷配合使用

## 0. 編輯優先序與忠實度邊界

### 0.1 忠實度與既有中文修稿

- 忠實翻譯優先於擴寫式說明
- 不可只為了讓中文聽起來完整，就自行補入原文未明示的步驟、因果、時間順序或背景知識
- smoothing 可以，invent 不行
- 修訂既有中文時，預設保留自然、正確且符合本輪要求的原句，改動須對應具體的語法、語意、指涉或語氣問題，或使用者要求的改寫目的。 若理由僅是某個成分可省略、改後較短或另一寫法也通順，則不足以支持刪改原句
- 判斷「我們」「了」「會」「一下」等成分的去留時，須核對它們如何表達原句的人稱、領屬關係、體貌、情態與語氣，將這些作用一併納入修稿的忠實度判斷

#### 補足背景時區分翻譯與解說

情境：使用者要求忠實翻譯「The ray starts at the camera and passes through a pixel sample.」，而來源僅交代射線的起點與路徑，未交代搜尋效率或可逆性

修改前：

```text
為了避免從光源發出的光線浪費計算，我們利用光路可逆性，從相機穿過像素樣本發射光線
```

修改後：

```text
射線會從相機出發，穿過一個像素樣本
```

改動理由：來源只交代射線從哪裡出發、穿過什麼，譯句便在這個資訊範圍內表達動作，保留與來源相稱的短句。 若要補入搜尋效率與可逆性，必須另外取得技術依據，並確認使用者授權將材料整理成解說正文

若使用者要求整理成解說文章，而且任務材料已經提供了從光源發射的浪費、可逆性與相機取樣的關係，就能依 [4.1 的幾何光學示範](#用模型的用途引入幾何光學假設)補足引入背景。 修稿時查閱任務來源與已接受前文，將尚未確認的前提記在工作筆記，繼續完成已有依據的內容

### 0.2 共現、時間關係與因果鏈

- 若 source 只是在表達共現、時間關係或關聯，不可無憑據把它改寫成新的流程順序或因果鏈
- 若 source 沒有明說施事者或操作主體，不要為了補齊中文句骨自行補出一個做事者
- 若 source 沒有明說結果或終點，不要為了讓句子有收束感而自行造一個結果補語

例：

- 避免：source 只說 `指令取回後`，中文擴寫成 `指令取回後會先解碼`，憑空補出下一步
- 優先：維持原句 `在取回指令後`，讓後續事件由 source 自己交代

### 0.3 Typo 與事實滑漏

- 若 source 含有明顯 typo 或事實滑漏，仍以忠實翻譯為主，並加上簡短譯者註，但不得直接將正文改寫成「修正後的版本」
- 譯者註應明示這是譯者觀察，不是 source 原文

### 0.4 評價力度、保留詞與玩笑

- 不可把 source 的輕微評價、保留詞或玩笑，升級成更強的稱讚、命令、舞台化語氣或 sales pitch
- 對 `good`、`nice`、`interesting`、`early`、`perhaps`、`maybe`、`we think`、`we wonder` 這類詞，中文應保留原本力度
- 若 source 只是平實介紹某書或論文在談什麼，中文也應優先維持平實介紹，不要自行補成 `強烈推薦`、`快去讀`、`之後你會感謝我們` 之類的讀者指令
- 若笑點高度依賴英語語境、文化梗或作者口條，中文直譯會顯得做作時，可將它縮成較平實的忠告，保留笑點的改寫也不得自行加戲

例：

- 避免：`一本絕佳的計算機結構書。 去讀`
- 優先：`一本有關計算機結構的好書`
- 避免：`這篇論文非常精彩，強烈推薦`
- 優先：`這篇論文很有意思`
- 避免：`別越過 GO，更重要的是，不要領那 200 元你很需要的遊戲幣`
- 優先：`在沒有先對硬碟有一定程度的了解前就讀 FFS，實在沒什麼道理`

## 1. 中文自然化與文章氣質

- 自然且精確的中文技術段落，優先於僵硬的說明書腔
- 若句子沒有錯字或明顯語病，讀起來卻像模板、宣傳或 AI 總結，仍須依任務要求重寫，連同文法之外的文氣一起檢查
- 若翻完後仍看得出明顯英文句骨，應直接重寫句子，而不是只補 glue word
- 優先讓動詞推動句子，而不是讓抽象名詞撐住子句骨架
- 翻譯時，若兩種寫法都合文法且忠實，通常取較自然的一種，修訂既有中文則依 0.1 核對原句是否需要改動，不以較短的版本作為預設
- 若英文把事件包進 nominalization、`preposition + V-ing` 或高密度名詞塊，中文通常依 `references/output_grammar.md` 的具體句法規則，將它還原成自然的事件子句
- 若中文已經很自然了，不要為了顯得完整而補一層解說，例如 `這代表...`、`換句話說...`、`這也意味著...`。 補充內容的來源與任務依據另依第 3 節核對

例：

- 避免：`一種常見方法`
- 優先：直接說清楚是哪個方法、做什麼用
- 避免：`這也意味著...`
- 優先：直接寫出實際結果或推論

## 2. 語域與語氣

- 盡量貼近原文的語域
- 若 source 明顯正式，譯文也應維持正式
- 若 source 明顯較口語，譯文可自然，但不可滑進原文沒有授權的俚語感
- 若 source 的段落只是平實說明，中文也應維持平實，不要補成宣傳文案或讀者命令
- 若 source 在某個位置保留不確定、推測、玩笑或輕微評價，中文也要保留同等力度

## 3. AI 腔與解說具體性

撰寫文章、提案、計畫、進度更新與完成回覆時，圍繞本輪目的交代事實、動作、結果、下一步行動及實際限制

- 審閱自行追加的澄清、排除、保證、不必做某事的補充與範圍說明時，逐句確認它回答了使用者哪個問題，或提供了哪項理解、操作及決策所需的資訊。 若刪除某項補充後仍能完整回答問題、交代結果及必要限制，就刪除該項補充，並繼續保留同句中的必要資訊
- 檢查補充內容時，以資訊為單位涵蓋句內附註、獨立句、跨句及跨段內容，逐項核對 `不是 A，而是 B`、`A。不會 B`、`不需要另看其他文件`、`不要求各建一個 class` 與 `原有修改沒有被覆寫` 等表達的任務用途。 即使改成肯定句、換詞或拆句，原有的補充資訊仍須按同一判準檢查
- 遇到 `只`、`才`、`僅` 等限定語時，核對它限定了哪個對象、條件或結果，再依這項限定對本輪任務的用途，刪除無用途的補充，直接交代需要的資訊、判準及動作
- 保留對比、否定、澄清或查驗結果時，須能指出來源位置、使用者的具體要求或實際工作紀錄，並依任務處理對應內容：
  - 翻譯來源明示的對比、否定或澄清時，忠實保留其資訊與力度
  - 回答使用者已提出的具體疑問、誤解或比較要求時，回應對應內容
  - 回報實際故障、未完成驗證或使用者明示要保留並確認的項目時，交代查驗結果
- 新增補充須有依據並能提供完成任務所需的資訊，內容可能正確、來自自己較早寫的筆記，或能預防自行假設的「常見誤解」，都不足以構成新增理由。 確認需要保留的重點後，將它直接寫成主句，交代本輪任務所需的內容
- 依來源與本句用途選擇引介方式：
  - 來源確實在定義術語時，可用 `所謂...就是...`
  - 來源支持推論關係時，可用 `這也意味著...`
  - 介紹檔案、工具或流程時，說明它的用途與行為
  - 陳述下一個事實時，直接承接該事實
- 文章與章節開頭依 [style 4.1](#41-文章目的背景與前提) 建立對象、問題及新主題的用途，再安排必要的導覽
- explanation-oriented writing 不可只列抽象類別名稱，必須交代具體檔案、具體責任、具體行為
- 若用了 workspace 內部術語，首次出現時要用白話展開
- 長句可以更精確，但長句應補足條件、動作、結果與因果，不要只把內部控制詞串成一串名詞
- 對 repo guide、workspace README、code report、workflow explanation、system overview 與風格檢查摘要，描述某個 layer、folder、file family 或 rule family 時，至少補出下列其中兩種具體資訊：裡面放了什麼、它控制什麼實際決策、agent 或使用者在什麼時候會讀它、它和相鄰層有何差異、一個代表性檔案或例子
- 若段落只說 `提升品質`、`確保一致性`、`建立清楚邊界`，但沒有交代具體對象、行為或判準，視為太抽象，改寫成可驗證的檔案、步驟、條件或結果
- 說明所需的施事者、因果鏈、時間順序與結果補語，都須依本檔第 0 節核對來源，不得為了讓敘述看起來完整而自行補入 source 未明說的資訊
- 教學式說明先依 4.1 建立理解所需的背景與問題，再介紹核心規則、進階條件與例外。 各項資訊在讀者需要它的位置展開
- 若要把理論規則轉成學習者版說明，輸出應包含可操作判準、必要例句、常見錯誤與延伸條件，但不要把理論標籤當成讀者必懂的前提
- 教學式輸出若需使用 Binding、topic、DP、VP 等語法概念，先用普通中文說明要檢查的關係，再補英文術語，一般翻譯輸出則不主動展示這些術語

例：

- 避免：`這裡主要處理術語邊界`
- 優先：`這裡主要決定哪些詞保留英文、哪些詞翻成中文，以及章節內第一次出現的詞要不要先做雙語介紹`
- 避免：`這段主要在處理 output contract`
- 優先：`這段主要在說明這次最後要交付的是完整譯文、review 報告，還是其他特殊形式的輸出`

## 4. 段落節奏與 Markdown prose

- 每段優先控制在 2-5 行，高密度段落通常應低於約 150 個中文字
- 短段落政策不等於 sentence-per-line 的硬斷行
- 正式輸出以乾淨 Markdown 為主
- 段落可在資訊忠實的前提下依需要重新劃分，不要求與 source 1:1 對應
- 對多個平行短項目，例如 loops、blocks、fields、units，可以使用 bullet
- 規格步驟敘述優先保留編號、縮短句尾、把動詞往前提
- 段落內包多層邏輯時主動重分段，而不是用分號硬串
- 若為了解說完整而把背景、條件、例外與結果全塞進單段，優先拆成「先判斷什麼」「怎麼改」「例外是什麼」三段或清單
- 若 source 以平實段落展開說明，譯文也依原有資訊推進，避免每段都追加總結句，以免過度總結而顯得像 AI 產出的教材摘要

### 4.1 文章目的、背景與前提

撰寫文章或章節開頭時，從讀者已知的內容建立講述對象與目前需要解決的問題，再說明即將介紹的概念、方法或模型能幫助我們理解什麼。 續章可承接前文已得到的結果，獨立文章可從讀者熟悉的使用情境或需求切入，背景則取自來源、已接受的前文與已確認的任務資料，新增事實仍依第 0 節核對忠實度

需要閱讀導覽時，將它放在讀者已理解主題用途的位置，讓各項內容的次序對應問題如何逐步得到解答。 寫出「先理解 A，才能理解 B」前，讀者應已知道 B 是什麼、為什麼需要理解 B，以及 A 如何提供所需的前提。 「先、再、最後」用來表達已有依據的時間、條件或解說次序，各步之間的承接仍須由對象、動作與目的交代

在開頭引入具體事件、方法名稱、圖名、映像檔或命令前，先介紹它們的用途，讓讀者取得理解後文所需的根據。 審閱「先看一個事件。」「本章先……」等開頭時，確認前文或所在段落如何建立對象與問題，若首句很短並立即收句，就核對它提供的背景及下一句承接的內容，調整句長或標點後再重新檢查

安排分段與導覽時，依任務決定篇幅，將必要的術語與前提放在使用它們的位置之前，前文已經交代了本節問題時便承接已知內容展開。 使用者要求操作步驟，或來源本身就是操作說明時，可依該任務直接交代動作，讓說明隨實際需求推進

安排段落時，先確定這一段要回答的核心問題，再逐句交代回答所需的資訊，讓下一段能處理尚未解決的問題、延續同一對象，或從已得到的結果引出新內容。 若下一段改換主題，就交代它與目前問題的關係，重述導覽或結論時則核對這一段增加了哪項讀者需要的資訊

例如，介紹座標轉換時，開頭從幾何資料會經過哪些操作，推進到組合操作的困難，再引入表示方法：

```text
幾何資料在不同座標系統之間移動時，會反覆經過縮放、旋轉與平移，如果每一種操作都採用不同的表示方式，我們便難以組合轉換順序，也不容易算出返回原座標系統的操作。 齊次座標會替位置增加一個分量，將這些轉換都表示成矩陣乘法，讓我們沿著矩陣的乘法順序，就能追蹤一個點轉換的過程了
```

第一句從縮放、旋轉與平移的操作背景，交代不同表示方式為何會妨礙轉換順序的組合，讓讀者知道接下來需要解決什麼問題。 第二句才引入齊次座標，說明它如何統一表示這些轉換，以及讀者如何沿著矩陣乘法追蹤一個點的轉換過程，讓新概念在需要它的位置出現

重新閱讀文章及各章節開頭時，指出讀者從哪項已知資訊開始、對象與問題在哪裡成立、新主題提供什麼幫助，以及導覽如何承接這些內容，並可用前文已建立的內容核對承接的根據。 若技術前提或因果仍缺少根據，就另記待查證事項，供後續回查材料

#### 課程材料改寫成概念解說

情境：使用者要把課程材料整理成可刊登的技術文章，材料已經交代了面積光源、局部遮擋與半影的關係

修改前：

```text
老師在投影片中介紹了面積光源的軟陰影。 課程說明，有些地方比較暗，有些地方比較亮
```

修改後：

```text
面積光源的不同位置可能受到不同遮擋，因此著色點即使看不見整個光源，仍可能收到部分區域的照明。 累加可見區域的貢獻，就能得到從明到暗逐漸過渡的半影
```

改動理由：改寫以光源各部分受到的遮擋為起點，說明著色點如何收到部分照明，再從累加可見區域的貢獻推進到半影的形成，文末仍保留材料與圖例的來源。 刪掉「老師介紹」後，正文仍須依材料提供的技術資訊講清楚概念，讓來源說明與概念解說各自承擔用途

#### 系列文章承接已知內容

情境：前章已經介紹了相機視角下的深度測試與局部著色，本章要解釋軟陰影、模糊反射與間接光照

修改前：

```text
前章講過光柵化，這裡不再說明。 接下來介紹光線追蹤
```

修改後：

```text
前面的章節中我們會用深度測試來找出相機看見的最近表面，再依著色點、材質與給定的光源來計算局部著色。 但如果要進一步去處理周圍表面的反射與遮擋，我們還需要查詢著色點朝其他方向看見哪些物體，以及那些方向送來多少光
```

改動理由：回顧取用前章已得到的最近表面與局部著色結果，讓讀者沿著這些已知資訊，理解本節為何還要查詢其他方向的物體與來光。 前章連結繼續提供完整推導，審閱時則核對本節接續的結果與新增的資訊需求，系列文章無須重新講解所有定義

#### 從所需資訊推進到既有方法的限制

情境：材料已經說明了全域效果需要其他位置的可見性與光照，而前章只使用相機深度圖和局部著色

修改前：

```text
這個流程的深度資訊只描述相機看見的最近表面，沒有記錄著色點朝其他方向會看見哪些物體。 局部著色也沒有計算那些物體會送來多少光，因此資料還不足以描述物體之間的遮擋與反射
```

修改後：

```text
要計算表面反射到相機的光，我們需要知道著色點從哪些方向收到光、各方向的光有多少，以及沿途是否受到遮擋。 但前章的相機深度圖只記錄了相機看見的最近表面，局部著色也沒有計算其他表面反射來的光，因此我們還需要補上其他位置的可見性與光照資訊
```

改動理由：先交代著色點所需的來光與遮擋資訊，讀者才有依據判斷相機深度圖與局部著色缺少哪些資料，後文也能接著說明如何用光線查詢取得它們。 比較範圍仍限於前章採用的流程，材料若已經說明了額外視角或預先計算能補充資料，就保留該資訊，讓限制與相應的補充方式一起呈現

#### 用模型的用途引入幾何光學假設

情境：文章已經提出了沿光路查詢遮擋與反射的需求，接下來要利用材料提供的直線傳播、光線互不干擾及表面反射、折射與吸收等假設，引入射線與物體求交的推導

修改前：

```text
我們先把光當成沿直線傳播的射線，並假設光線可以互相交錯，每條光線在交錯後仍會沿原本的方向傳播。 當光線碰到物體表面時，表面則會讓光線反射、折射或吸收部分能量
```

修改後：

```text
要沿著光路找出物體之間的遮擋與反射，我們需要把光的傳播表示成能與場景幾何求交的形式。 幾何光學會將物體之間的光路近似成直線，讓每段光路都能用起點與方向表示，再藉由求交找出下一個表面

在這個模型中，光線交錯不會改變彼此的傳播方向，因此我們可以獨立追蹤各條光線，再累加它們的貢獻。 光碰到表面後，會依材質計算反射、折射與吸收，並沿新的方向繼續查詢，如此一來我們便能逐段建立光路了
```

改動理由：讀者先知道要把光路轉成與幾何求交的形式，才能理解直線近似如何支援起點與方向的表示，以及光線互不干擾的假設如何支援獨立追蹤。 改寫讓每項假設都接回後文要做的操作，透過模型的用途建立引入理由

若後文要從相機搜尋光路，還需依材料交代搜尋效率與可逆性的關係，讓讀者理解為何從相機出發。 材料已經提供了這些關係時，可從「大量光源光路不會進入相機」引出搜尋需求，再說明哪些光路能反向追蹤，最後接到像素光線的產生

已經交代了目標與資料後，操作步驟可寫「先找出最近交點，再檢查光源可見性」，其中的「先／再」表達有依據的順序

### 4.2 句首承接、段落主線與語態

句子開頭用來建立本句講述的對象或背景，這個主題位置可承接前文的對象、結果、問題或條件，讓讀者知道本句沿著哪項已知資訊繼續。 若承接的是事件發生的時間或條件，也可用相應框架建立起點，再依 grammar 2.3 選擇自然的中文句骨

段落可以持續沿同一對象增加條件、動作與結果，也可以讓前句重要的新資訊成為下句的已知背景，每次轉換都要核對前後承接的對象與根據。 例如，[寫回的例段](#44-例子與推導融入正文)從既有值、操作結果與遮罩的設定開始，讓讀者沿著這些設定，理解如何取出位元並組合成新值

選擇語態時，先核對段落沿著哪個對象展開：沿做事者說明，就交代做事者及其動作，沿本句要強調或段落持續追蹤的受事說明，則可將受事留在句首，再交代施事與動作。 保留被動表述仍須依 [grammar 2.6](output_grammar.md#26-把--被--受) 指出前後文或文章問題的依據，例如同一事實可接入下列兩種前文：

- 我們要看蜜蜂在傳播過程中做了什麼：「蜜蜂傳播花粉」
- 花粉如何傳到別處：「花粉由蜜蜂傳播」

第一個例句承接蜜蜂在傳播過程中的行為，第二個例句承接花粉如何傳到別處的問題，因此兩句雖保存同一事實，句首追蹤的對象卻不同。 第二句以已明示的問題對象「花粉」為主線，符合受事為重點的條件，具體句法仍依 grammar 2.3 與 2.6 核對

確認講述對象後，依來源與緊鄰上下文判斷主詞如何表達：

- 來源未交代施事者時，保存資訊缺口
- 主詞已由緊鄰上下文清楚承接時，保留自然省略
- 切換主體或有多個候選時，明示有來源依據的主詞

重新閱讀段落時，逐句說出本句從前文承接了什麼、增加了什麼，以及下句如何使用這項新資訊，讓銜接能落在具體的對象與根據上。 若兩句之間只有連接語，仍需回到來源補查事件關係，再依 grammar 2.8 表達已確認的條件、時間、轉折與因果

#### 將段首短斷言改成有因果的敘述

情境：前文已經說明了每個像素要查詢多條光路，本段需要比較這些計算與即時、離線算繪的時間預算

修改前：

```text
這些光路查詢會增加計算量。 每個像素可能需要多條光路，而每條光路又可能包含多次求交與著色。 即時算繪需要在很短的時間內完成一張圖，離線算繪則能花更多時間估計這些光路的貢獻
```

修改後：

```text
由於每個像素可能會需要估計多條光路，而每條光路又可能包含多次求交與著色，因此光線追蹤的計算量也會隨著這些查詢增加。 在即時算繪的情況下，我們往往需要在很短的時間內完成一張圖，因此能分配給光路估計的時間有限，效果可能會比較差，所以以往這通常會用在離線算繪中
```

改動理由：第一句承接前文的光路查詢，交代每個像素的光路數量與每條光路的求交、著色如何形成計算成本，第二句再說明時間預算如何限制可做的估計。 多個完整長句沿著同一問題展開條件、動作與結果，平行的短說明則依[文法的段落與清單規則](output_grammar.md#41-段落換行bullet-與-list)安排為清單

重新閱讀時，辨認每個句點切開的資訊如何接續，從條件、動作與結果的關係重組敘述，避免把「查詢很重要。 計算很昂貴。 時間有限。」直接換成逗號，或靠重複主詞和連接詞拉長句子。 來源支持的短條件句，例如「若沒有交點，就回傳背景值」，在操作步驟或公式推論中仍可直接表達結果

### 4.3 主詞、動作與收束處的重點

句子提出主體後，應盡快交代它的主要動作或狀態，若主詞與動詞之間插入過長的說明，就依插入內容的資訊角色，將它安排到背景句、前置框架或獨立句。 必要的長定語仍須保留完整關係，句長與詞數用來找出值得重新檢查的位置，再由上下文判斷如何調整

核對句子描述的是誰讀取、比較、選擇或寫回哪項資料，再用適當動詞交代這些實際動作，定義、分類與狀態則依 grammar 保留自然述語。 完成事件、新狀態與慣常行為依 grammar 2.5 判斷「了」的位置，例如「這個介面現在穩定了」交代已成立的新狀態，慣常啟動程序則沿該節的無標記或「會」表述

安排子句、句子或段落的收束時，將值得讀者記住的重要新資訊放在完整結束的位置，讓整個述語、結果或已引介的列表取得清楚的強調位置。 句末體貌詞仍隨所屬述語保留，標點依 grammar 選擇，連同述語一起完成自然的收束

在[寫回例段](#44-例子與推導融入正文)中，保留高位元與更新低位元的計算逐步得到 `0xA5`，段落便以這個新值收束，讓讀者記住寫回操作的結果。 後續的參數清單或背景依其用途另作安排，多項同等重要的結果則各自形成完整的子句、句子或列點，讓每項重點都有可辨認的位置

重新閱讀時，核對主詞提出後何時才出現主句動作、實際作用關係是否由動詞交代，以及讀者在收束時記住的內容是否就是本段重點。 長插入、句末附註與多項結果一併依上下文判斷

### 4.4 例子與推導融入正文

解釋操作或推論時，在讀者需要具體資料才能繼續理解的位置引入例子，先交代追蹤後續步驟所需的設定。 計算或操作的每一步都要對應正在解釋的規則，得到結果後再接回正文的問題，讓讀者理解這個例子如何支持說明

#### 讓算例的設定與結果回應正文問題

情境：段落要解釋 stencil write mask 如何決定寫回值，材料已經提供了既有值、操作結果與遮罩的意義及位元運算

修改前：

```text
我們先設既有值為 0xA2、操作結果為 0x35、遮罩為 0x0F，再算出結果 0xA5
```

這段直接給出三個數字與答案，讀者還不知道哪些位元要保留、哪些要更新，也無法由文字追蹤答案如何形成

修改後的完整算例如下，從遮罩要做的選擇引入三項設定，逐步算出寫回值：

```
Stencil write mask 會逐 bit 選擇 stencil attachment 是要保留既有值，還是採用 stencil operation 算出的新值。 假設目前具有下列資料與設定：

- 既有 stencil 值：$S_{\mathrm{old}}=\mathrm{0xA2}$
- Stencil operation result：$S_{\mathrm{operation}}=\mathrm{0x35}$
- Application 設定的 stencil write mask：`glStencilMask(0x0F)`，所以 $M=\mathrm{0x0F}$

將三筆 8-bit 資料展開後，可以得到：

$$
\begin{aligned}
S_{\mathrm{old}}
&=\mathrm{0xA2}=1010\,0010,\\
S_{\mathrm{operation}}
&=\mathrm{0x35}=0011\,0101,\\
M
&=\mathrm{0x0F}=0000\,1111.
\end{aligned}
$$

Write mask 中的每個 bit 都會決定結果中同一個 bit 的來源：

- Mask bit 為 $0$：沿用 $S_{\mathrm{old}}$ 中對應的 bit
- Mask bit 為 $1$：採用 $S_{\mathrm{operation}}$ 中對應的 bit

依照上述逐 bit 選擇的規則，`0x0F` 的高四個 bits 都是 $0$，所以新值會保留 $S_{\mathrm{old}}$ 的高四個 bits。 遮罩的低四個 bits 都是 $1$，這部分則採用 $S_{\mathrm{operation}}$ 的低四個 bits，將允許寫入的操作結果放入新值

在 8-bit 範圍內，將 `0x0F` 的每個 bit 逐一取反，就會從 $0000\,1111$ 得到 $1111\,0000$，也就是 `0xF0`。 管線會先使用 `0xF0` 取出既有值中需要保留的高四個 bits：

$$
\mathrm{0xA2}\mathbin{\&}\mathrm{0xF0}
=\mathrm{0xA0}.
$$

接著使用 write mask `0x0F` 取出 operation result 中允許寫入的低四個 bits：

$$
\mathrm{0x35}\mathbin{\&}\mathrm{0x0F}
=\mathrm{0x05}.
$$

最後再對兩部分執行逐位元 `OR`，組成準備交給 framebuffer write 的 stencil 值：

$$
\begin{aligned}
S_{\mathrm{new}}
&=\mathrm{0xA0}\mathbin{|}\mathrm{0x05}\\
&=1010\,0000\mathbin{|}0000\,0101\\
&=1010\,0101\\
&=\mathrm{0xA5}.
\end{aligned}
$$

因此，新值的高四個 bits 來自既有 stencil 值 `0xA2`，低四個 bits 則來自 operation result `0x35`。 Stencil write mask 最後交出的結果是 `0xA5`，framebuffer write 會使用這筆結果來更新 stencil attachment
```

例子以遮罩決定各位元來源的規則引入既有值、操作結果與遮罩，讓讀者理解為何要分別取出高四個位元與低四個位元，再將兩部分組合成 `0xA5`。 最後一段從組合結果接回模板附件的更新，讓算出的新值繼續參與正文所說明的寫回操作

重新閱讀例子時，從已交代的設定逐步核對每個中間結果的根據，並確認最後結果如何支持正文正在解釋的操作或推論。 若來源缺少前提或中間根據，就記錄待查證資訊，新增的背景、施事、因果及結果仍依第 0 節核對忠實度

## 5. 規則示範與任務參考的用途

使用者明示外部文風參考時，依指定範圍讀取，將其中與本輪行文及結構相關的選擇作為參考。 續改既有文章時，連同目前章節與相鄰已接受內容一起閱讀，沿用已建立的術語、引用形式、段落主線與節奏
