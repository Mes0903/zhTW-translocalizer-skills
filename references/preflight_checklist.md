# 開工前檢查表 v2.1

起草、修稿或調整規則前，使用本檔整理的操作清單逐項核對 `references/workflow.md` 所要求的前置事項，完成本輪適用的全部項目後，才能開始起草。 各項判準依規則正文檢查，本檔僅整理需要執行的核對工作

欄位名、Mode 名與其他 workflow 標籤供 agent 判定內部狀態，正式輸出需要提到這些概念時，則改寫成完整句子，說明實際要做的事

## 1. 輸入與模式

- [ ] 確認來源檔案、來源範圍與本輪改寫目的，或確認它們可從 `action` / task state 推導。 逐字稿整理或系列解說依 style 0.1、4.1 核對來源講述方式與系列承接
- [ ] 確認輸出檔路徑，或確認它可從 `action` / active file / task state 推導
- [ ] 確認 baseline：
  - [ ] explicit path / path list
  - [ ] `auto`
  - [ ] 欄位缺漏，視為 `auto`
- [ ] 確認這次最後要交付什麼形式的內容：
  - [ ] 完整正式輸出
  - [ ] review / report 類中介成品
  - [ ] 其他特殊結構輸出
- [ ] 確認 `action` 已經提供了
- [ ] 整理使用者這一輪明確要求你做的事：
  - [ ] 本輪工作目的
  - [ ] 額外必讀 file / dir / source paths
  - [ ] 自訂輸出章節、區塊順序或標題骨架
  - [ ] 原文 + 譯文 / 譯文 + 解釋 / 其他雙層輸出形式
  - [ ] custom CSS / raw HTML / artifact allowance
- [ ] 整理 linter 要怎麼跑，以及是否有 rule-level 例外
- [ ] 檢查 `python3` 為 Python 3.10 以上，並確認 linter 可執行
- [ ] 確認 skill root 下的 `linter/lint.py` 入口可用，從其他目錄啟動時使用完整的程式路徑
- [ ] 判斷這一輪是不是在接續同一個任務，還是使用者已經明確改成了另一個任務
- [ ] 若這仍是同一個任務，沿用既有的 source paths / output / scope / baseline / 交付形式 / action / mode / citation / 已經接受的例外
- [ ] 若使用者已經明確重新綁定了任務，重新跑對應的開工前檢查，不可默默沿用舊 task 狀態
- [ ] 檢查使用者是否給了任何與 workspace spec 衝突的明確特殊要求
- [ ] 區分目前的 action 哪些只是任務參數，哪些其實是在要求破例
- [ ] 若有衝突，起草前先停下並列出：
  - [ ] 使用者要求
  - [ ] 衝突條款
  - [ ] 接受 override 後的影響
- [ ] 詢問是否仍要在該 override 下繼續
- [ ] 在使用者明確確認或撤回衝突要求前，不可開始起草
- [ ] 檢查 `context memory dir`：
  - [ ] `none`
  - [ ] 已經提供了 path
- [ ] 若提供了 path，且 `<PATH>/context_memory.md` 存在，先讀它
- [ ] 若提供了 path 但檔案尚不存在，規劃在第一個穩定 checkpoint 建立它
- [ ] 判斷本輪主要工作重點：
  - [ ] 主要在翻譯或重寫 source
  - [ ] 主要在解說 code / repo / workflow
  - [ ] 主要在 review / revision 既有文字
  - [ ] 主要在調整規則 / linter / prompt / workflow
- [ ] 判斷這次是新檔還是續改：
  - [ ] Mode A：output file 不存在或為空
  - [ ] Mode B：output file 存在且非空
- [ ] 檢查專案附近是否存在 project-local glossary

## 3. 參考依據收集

- [ ] 在起草前先依本輪工作重點整理要讀哪些參考資料
- [ ] 若使用者明確指定 must-read file / dir / docs，先把它們放進閱讀計畫，不可被 generic 預設覆蓋
- [ ] 決定這次真正要沿用的 baseline：
  - [ ] 若使用者明確指定 path 或 path list，讀那些 Markdown baseline
  - [ ] 若為 `auto`，且這是新任務，使用守則中的相關段落示範
  - [ ] 若為 `auto`，且這不是新任務，讀目前 task 中先前已經接受的 Markdown，包括目前 output scope 前面緊鄰的已經接受的內容，以及同一 task 中明確相關的較早 Markdown
- [ ] 確認 baseline 只作為文風 / 結構參考與延續性錨點，不覆蓋 source text、glossary 或 citation 決策

閱讀要求以 `references/workflow.md` 3.2 為準：

- [ ] 依主要工作重點與 mode 完成該節的必讀項目
- [ ] 翻譯或重寫時，分別保存術語對照與中文文風參考，中大型 scope 另備涵蓋各批次的用語及格式一致性計畫
- [ ] 解說程式或 repo 時，已經讀了相關程式、文件與 README，並完成了該節的文風參考要求
- [ ] review 或 revision 時，已經讀了目標文字、已經接受的 baseline、目前文章及相鄰已經接受章節，以及忠實度判斷所需的來源。 使用者已經指出的問題依已知範圍一併檢查
- [ ] 調整規則或 linter 時，已經讀了 benchmark、退化案例、目標文件與目前實作。 具體退化所需的原件與來源依該節補讀

- [ ] 若本輪會修訂既有正式輸出檔，標記受影響範圍：
  - [ ] 動到 opening sentence / opening paragraph
  - [ ] 動到 explanation-oriented paragraph
  - [ ] 動到 citation 或 hyperlink 行為
  - [ ] 動到 LaTeX / Markdown / HTML 結構

## 7. 自然化與 Markdown 規劃

規劃文章與段落時，依 [workflow 5.1.1](workflow.md#511-起草前的文章與段落安排) 整理內容順序，再用 [style 4.1 至 4.4](output_style.md#41-文章目的背景與前提) 核對背景及例子如何展開，並依 grammar 第 2 節檢查句法。 下列項目用來確認實際安排是否符合各項適用規則

- [ ] 讀完來源後，已經按任務範圍整理了文章問題、對象、前提、新資訊及下文依賴，並選讀了 workflow 3.3 對應的壞例與好例
- [ ] 已經依段落安排回查了適用的 grammar，並記錄了選擇理由與來源位置
- [ ] 已經決定了重新閱讀時如何核對句首承接、主線、主詞與動作、收束處重點。 介紹新方法而需比較既有作法時，依 style 4.1 核對動機、需求、既有方法限制與方法用途的順序。 假設依 style 4.1 核對支援哪個建模操作或推導，算例依 style 4.4 核對設定及各步根據
- [ ] 依 grammar 2.6 逐句核對全部被動表述的保留條件，並另行標記需要改寫結構的名詞化過重句子
- [ ] 標記 `preposition + V-ing` 或事件名詞化片語，判斷是否應還原成動詞子句 / 時間框架
- [ ] 標記 `名詞組 + 的 + 動詞組` 與其他高密度 `的` 字名物化，確認它們是否真的有資訊壓縮價值，而不是把事件硬壓成書面名詞短語
- [ ] 標記看似術語、其實仍可拆開或擴充的中文組合，確認是否不該硬寫成固定詞
- [ ] 標記可能涉及字、音節、詞素與詞邊界的詞彙，確認沒有把「兩個字」直接當成「兩個詞」或把可拆短語硬收成固定詞
- [ ] 標記可能是離合詞、述賓複合詞或述補複合詞的中文動詞，確認是否需要允許體貌、數量、修飾或賓語相關成分插入
- [ ] 標記新詞、音譯、縮略、轉類、派生或專名普通化用法，確認保留、翻譯或加註策略有 source / glossary 支撐
- [ ] 標記若改用不同中文詞類會改變 `很`、`對`、賓語或補語配置的句子，確認目前詞類選擇是否自然
- [ ] 標記詞類判斷是否只靠單一例句或單一測試下結論。 若是，回頭檢查位置、賓語、`對 / 關於`、否定、A-not-A、體貌標記與 `的` 修飾
- [ ] 標記功能詞是否被硬塞成一般名詞或動詞，特別是數量、體貌、語氣、修飾關係與 clause 邊界標記
- [ ] 標記沿來源線性順序寫會切錯修飾範圍或成分邊界的句子，必要時先重排
- [ ] 標記有歧義的修飾範圍或成分邊界，先做替代、省略、移位、問答與協調測試，再決定譯文結構
- [ ] 不符合 grammar 2.6 保留條件的被動表述，已經規劃了如何改用主動、無主句或框架先行
- [ ] 保留被動表述時，已經確認了受事是本句要強調或段落持續追蹤的對象，並記錄了文章問題或前後文的具體依據
- [ ] 標記未明說施事者的 `被` 句是否被草稿自行補出做事者。 若是，檢查來源或上下文是否真的提供依據
- [ ] 標記 `被` 句是否額外製造了受害 / 蒙受語氣。 若來源只是中性事件，不要平白加重成受害式 `被` 句
- [ ] 標記 `受 / 受到` 是否只是被動句替代詞。 若語義不是真正的承受或受影響，不要硬改成 `受` 句
- [ ] 標記 `受 / 受到` 後面是否其實接了 bare V、結果補語、雙賓語或內外賓語結構。 若是，不要硬改成 `受` 句
- [ ] 標記 `受 / 受到` 是否更適合接名詞化補語，如 `批評 / 攻擊 / 影響 / 責備 / 處罰`
- [ ] 標記名詞修飾堆疊或長 `...的...的...` 鏈，判斷是否應改寫成動詞結構或拆開
- [ ] 標記帶有明顯結果狀態的操作，判斷是否更適合結果補語
- [ ] 標記可能用 `把` 字句表達得更清楚的處置 + 結果句
- [ ] 標記 `把` 後名詞是否其實是一般無定短語。 若是，優先保留普通主動句
- [ ] 標記 `把` 字句是否缺乏明確終點、結果或收束點。 若缺乏，不要只為了中文化而硬套 `把`
- [ ] 標記 `是` 在句中究竟是在做普通判斷，還是在標出焦點。 若只是一般敘述，不要硬加焦點標記
- [ ] 標記 `A 是 B` 究竟是在分類、等同辨識，還是在說明部分與整體。 不要把普通判斷句當成可逆等號句
- [ ] 標記 `有` 在句中究竟是領屬、存在，還是完成貌。 若後接定指名詞，檢查是否其實不適合存在句
- [ ] 標記 `是...的` 與 `...的是...` 是否真的承擔焦點 / 辨識功能，而不是只是增加句型花樣
- [ ] 標記單寫 `自己` 是否同時有多個第三人稱候選先行語。 若有，規劃改成明示名詞或 `他自己 / 她自己`
- [ ] 標記局部從句裡的 `我 / 你` 是否會阻斷原本想要的第三人稱 `自己` 照應
- [ ] 標記句內其他第三人稱參與者、領屬者或多個 `自己` 是否讓照應路徑變得不穩
- [ ] 標記言說 / 態度動詞下的單寫 `自己` 是否不必要地引入主語或說話者觀點
- [ ] 標記 `他 / 她 / 它` 是否其實在承擔局部反身指涉。 若是，規劃改成 `自己`、`他自己 / 她自己` 或重複名詞
- [ ] 標記代詞是否受 `每 / 所有 / 沒有` 等量化詞約束，確認它是固定指稱、bound variable，還是需要改成描述式名詞組
- [ ] 標記條件句或前文無定名詞引出的代詞，確認是否為 donkey pronoun 類讀法，避免誤譯成固定指稱
- [ ] 標記 bare conditional 中疑問詞或代詞變體是否需要 `就` 來連接條件與結果
- [ ] 標記 `V 得 ...` 後是否保留了不自然的顯性賓語，確認它是結果補語還是描寫補語
- [ ] 標記動詞後成分到底是 object、complement、result、duration / frequency 還是 adjunct，不要全部當成賓語
- [ ] 標記能回答 `什麼`、`怎麼`、`多久`、`幾次` 的成分，確認動詞後區域是否需要重排或拆句
- [ ] 標記動詞後是否同時堆了賓語、結果、頻率或持續短語。 若動詞後結構過重，先規劃重寫
- [ ] 標記同一主題連續出現、可減少重複主語的子句序列
- [ ] 標記前置的名詞組、賓語或數量短語，確認它們是否真的形成自然的話題 / 情境框架，而不是只是表面換序
- [ ] 標記前置的 `[數詞 + 量詞 + 名詞]` 數量短語，確認句子焦點是否真的落在數量本身。 若不是，避免直接話題化
- [ ] 標記光桿名詞是種類、有定還是無定讀法，不要直接套英文冠詞邏輯或每次都補 `一個`
- [ ] 標記 `們` 是否只是英文 plural 的機械轉換。 非人名詞、抽象名詞或物件名詞加 `們` 時，確認是否已有群體化語境
- [ ] 標記若省略 `的 / 地 / 得` 會讓修飾或補語結構模糊的地方
- [ ] 標記高風險虛詞與小標記：
  - [ ] `的 / 地 / 得`
  - [ ] `了`
  - [ ] `把 / 被`
  - [ ] `就 / 才 / 再 / 還`
  - [ ] `因此 / 然而 / 於是 / 此外`
- [ ] 標記事實敘述、慣常行為、定義句與能力敘述，避免英文時態觸發多餘的 `了`
- [ ] 標記界線明確且帶結果的完成事件，依 grammar 2.5 判斷動詞後或句尾的 `了` 是否自然
- [ ] 核對正文、條件從句與核取項目中表示完成的「已」，依 grammar 2.5 優先展開為「已經」並搭配「了」，一併區分定語及「已知／已有」等詞的用法
- [ ] 標記狀態變更或 discourse update 句，判斷是否可使用句尾 `了`
- [ ] 標記 `著` 是否真的表示持續狀態、姿態或附著狀態，不要拿來翻所有 progressive
- [ ] 標記 `過` 是否真的表示經驗或曾發生，不要拿來翻一般完成結果
- [ ] 標記 `about to / soon / nearly / on the verge of`，判斷是否更適合 `快要……了 / 就要……了`
- [ ] 標記被否定的完成事件，判斷是否應用 `沒 / 沒有` 而不是 `不`
- [ ] 標記含數量詞的子句，確認 `V了 + 數量短語` 與句尾 `了` 是否會帶來不同解讀
- [ ] 標記可能需要簡潔連接詞如 `同時 / 但 / 因此 / 此外` 的子句關係
- [ ] 標記採用框架先行順序後會更聚焦的地方
- [ ] 依 style 4.1 標記尚未交代對象與問題，就開始指示閱讀、列方法或安排導覽的文章及章節開頭
